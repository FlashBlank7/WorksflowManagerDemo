# 管家的样子

> 一个工具值不值得留在终端里，很大程度取决于它长什么样、说话什么调子。
> 这里写清楚 guanjia 的取舍，改界面时对照着来。

## 一句话

**终端出身的工具，网页是它的另一张脸——不是另一个产品。**

## 三条原则

### 1. 品牌不占颜色，颜色只表达状态

大多数面板用满屏品牌色，于是"这块是绿的"既可能是品牌也可能是"正常"——
分不清的颜色等于没有信息。

guanjia 反过来：界面是**墨与纸**（暖灰阶），一见到饱和色就一定在说某件事的状态。

| 颜色 | 只用来表示 |
| --- | --- |
| 绿 `--ok` | 成功、健康 |
| 琥珀 `--warn` | 停摆、需要留意 |
| 红 `--err` | 失败、坏了 |
| 灰 `--faint` | 还没有结论（在跑、等人工确认） |

品牌强调靠**字重与留白**，不靠颜色。

### 2. 两张脸一眼同源

网页壳的标识用的是 REPL 的提示符 `❯`——你在终端里天天看见的那个符号。
数据（时间、id、数字、状态）一律等宽字体并对齐小数位；正文用比例字。
终端出身的工具，数字对得齐比"好看"要紧。

### 3. 说人话，且说完就给下一步

- 报错要说清**是什么**和**接下来做什么**：
  「定时没按时开火：上次 08-19 00:00，本该 08-27 00:00 UTC」
  后面必须跟得上「先手动跑一次确认工作流没问题，再看调度器还在不在」。
- 不确定就说不确定。「等」不是「坏」——还在跑就如实说还在跑，
  别为了页面整洁把它归进某个已知档位。
- 不造代号。构建工作流的那个东西就叫**构建智能体**，
  不要求用户先学会一套黑话才能读懂界面。

## 语气

管家是**安静、在场、不邀功**的：

- 好的时候一句话带过（「14 个已发布工作流都正常」），不铺排。
- 出事时把话说完整，但不惊慌、不甩锅——「构建仍在远端进行」比「跟踪失败」有用。
- 从不代替用户下判断。体检说「这几个要留意」，不说「你应该重建它们」。

## 具体约定

- 圆角 `--radius:10px`：比消费级产品方一点，工具感。
- 阴影极轻——层次靠留白和 1px 分隔线，不靠浮起。
- 状态符号固定：`✓` 成功 · `✕` 失败 · `⏸` 停摆 · `⋯` 进行中 · `⊘` 已取消 · `⏰` 定时触发。
  CLI 与网页用同一套，换个界面不用重新认。
- 中文界面里不混英文术语（除非那是命令本身，比如 `guanjia run`）。
