# 已知边界（不承诺、不宣传）

> 开源项目该有的诚实：这里列的是**现在确实做不到或没验证过**的东西。
> 发现新的边界就往里加，做到了就挪走并写进 CHANGELOG。
> 对齐版本：0.7.0（2026-08-29）。

## 必须自托管后端

guanjia 是**薄客户端**，本身不跑模型、不存业务数据。没有远端平台它只能做一件事：
告诉你还没登录。这是刻意的取舍（智能体循环在服务端才可审计、客户端无法伪造结果），
代价是**你得先自己跑一个工作流平台**（参考实现见项目主页的「后端」一节）。
没有托管版。

## 客户端

- **单远端会话**：可以存多个远端档案并切换，但同一时刻只连一个；
  没有"同时看两个环境"的视图。
- **网页壳是单用户界面**：默认只监听 127.0.0.1，没有多人同时使用的设计
  （多人请各自跑各自的壳，连同一个远端）。`--host 0.0.0.0` 能对外开放，
  但那只是"能连上"，不是"能多人用"。
  2026-08-29 起**回环也要访问密钥**：在多用户主机上，
  "能连到 127.0.0.1 的人就是你"这句话不成立——同机任何账号打开这个地址，
  背后就是你的平台令牌。确定独占一台机器的可以 `--no-key`。
- **会话历史只在本地**：`~/.guanjia/sessions/` 不同步、不备份；换台机器就没有了。
- **移动端未验证**：网页壳做过窄屏适配，但没有在真实手机上测过。
- **Windows 未验证**：只在 Linux 上真机跑过；Tab 补全依赖 bash/zsh。

## 依赖平台的部分

以下能力取决于你连的后端版本；老版本上会**静默降级**而不是报错：

- 工作流体检（`/api/v1/health-report`）——没有就跳过体检项
- 调度器健康（`/api/v1/scheduler/health`）——没有就显示"未知（远端版本较旧）"
- 运行产物下载、有界事件列表、运行归因——没有就相应地少一块信息

## 生成能力的边界

- **搭建质量受限于后端的积木库**，不只是模型。实测：积木库缺一个字符串函数时，
  同一需求的搭建时间从 40 秒变成 24 分钟，并被迫用 LLM 做本该确定性的计算。
  遇到"它绕了很久还没搭出来"，先看是不是积木层缺东西。
- **复杂需求仍需要来回**：构建智能体会在构建中提问，答得越具体越快；
  一句话搭出复杂业务流不是常态。
- **修复不是万能**：`repair_workflow` 对结构性错误有效；如果失败源自上游数据源本身
  （接口挂了、字段改了），修的是工作流对它的适配，不是数据源。
- **不能回滚到上一个版本**。平台会存下每次发布的快照（真机上已经有工作流存了三版），
  但没有「把旧版重新发布」这条路——新版把事情搞砸了，恢复手段是**继续往前修**，
  不是退回去。说「哪里不对」让它在现有基础上改，比重来一遍准。
  （对话里问「能回滚吗」，管家会如实说不能，不会假装做得到。）
- **返修可能在追一个不存在的能力**：积木层没有的能力，返修再努力也造不出来。
  实测一次返修为了"去掉文本中间的换行"空转 651 秒后超时——那个函数根本不存在。
  返修久久不结束时，值得先确认要它做的事在积木层做不做得到。

## 验收的边界

- **验收判错的代价比不验收更高**。监理出的卷子是模型生成的，可能出错；
  最贵的一种是它换掉了你给的输入却沿用你给的数字，于是判一个正确的工作流不合格，
  再把你引去"修"一个没坏的东西。
  判不合格时，验收单会附上**你当初逐字说的那句话**（原样存的，没经过转述）。
  **先拿它跟用例对一遍**：考的跟你说的不是一回事，就是卷子错了，
  换个自洽的例子重验即可；对得上才轮到修工作流。
- **例子要自洽**：输入和期望结果必须是配套的一对。换了输入就要换期望值。

## 收起来（归档）意味着什么

「收起来」是可逆的，也不删任何数据。收起来之后：

- **不再出现**在工作流列表、体检、近期失败里——收它就是为了别再管它
- **定时不再触发**（收起来时管家会把这一点说出来）
- **历史统计仍然算数**：今日运行数、近 7 日活跃条里还包含它跑过的次数。
  这是有意的——收起一个工作流不该改写平台已经发生过的事
- 说「拿回 X」即可恢复，列表、体检、定时一起回来

## 运行与调度

- **定时逾期检测有 90 分钟宽限**：调度器抖动与任务耗时都在这个窗口里，
  所以"刚过点几分钟没跑"不会报，真出问题会在下一次体检时报出来。
- **`guanjia run --follow` 只是跟随**：Ctrl+C 停的是跟随，运行仍在远端继续。
- **人工输入节点**：CLI 跑到 `paused` 会告诉你在等哪个节点，但填表要去网页壳
  或在对话里回答，命令行不能直接填。

## 安全边界

- **本地只存会话令牌**（`~/.guanjia.json`），密码不落盘；但令牌是明文存的——
  它的权限等同于你的账号，别把这个文件带出机器。
- **网页壳不做登录**：它只有一把一次性访问密钥（URL 带 `?k=`，随后种进 Cookie）。
  2026-08-29 之前这把钥匙只在 `--host` 放开时才生成，回环绑定假设
  "能访问 127.0.0.1:7800 的人就是你"——**多用户主机上这句话不成立**，
  同机任何账号打开这个地址，背后就是你的平台令牌。现在回环也要钥匙，
  确定独占一台机器的可以 `--no-key`（启动时会说清代价）。
  但钥匙终究只是"别让人随手就能用"，**不是认证**——公网暴露仍然不安全，
  远程访问请走 SSH 端口转发（`ssh -L 7800:127.0.0.1:7800 <主机>`，
  在远程机器上跑 `guanjia web` 时终端会直接印出这句）。
- **产物下载经本地壳透传**：文件内容会过一遍你的机器；沙箱产物的可信度取决于平台侧。

## 还没做的（不是缺陷，是没排期）

- 未发布到 PyPI / GitHub（等仓库与凭据）
- 桌面壳只是 `--app` 开独立窗口，没有原生打包与自动更新
  （[评估结论](decisions/desktop-shell.md)）
- 对话内没有工作流结构可视化（要看结构得导出 JSON）
- 没有工作流之间的编排（一个工作流调另一个由平台侧支持，客户端没有对应界面）
